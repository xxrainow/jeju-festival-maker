축제를 열고 싶은 제주 도민(마을회, 상인회, 지역 생산자 단체, 소규모 기획자)이
전국 축제 트렌드와 제주 데이터를 근거로 **축제 아이디어 → 제주 데이터 확인 → 기획안 → 홍보물**을 받는 AI Agent입니다.

「제주 AI·빅데이터 활용 AI Agent 개발 챌린지」 출품작 (마감 2026-11-20).
MVP는 소규모 1~2일 축제입니다. 문체부 2026 조사표에 1일 축제가 없어 예산 비교는 2일 이상 축제를 기준으로 합니다.

## 무엇을 하나요

| 단계 | 하는 일 | 근거 데이터 |
|---|---|---|
| 1. 조건 입력 | 한 문장("대정읍 방어 축제, 상권 활성화, 겨울, 가족, 예산 1천만 원")을 지역·목적·소재·예산·계절·대상 칸으로 나눈다. 사용자가 고친 뒤 확정 | 행정동 43개 이름 |
| 2. 아이디어 카드 3장 | 전국에서 늘고 있는 축제 형식 × 제주 재료 후보를 코드가 점수로 줄 세우고, LLM이 서로 겹치지 않는 3개를 골라 카드 문장을 쓴다 | 문체부 지역축제 2024~2026, 문화관광축제 지정 명단, 제주 재료 사전 |
| 3. 제주 데이터로 확인 | 고른 아이디어를 확인 도구 5개(시기, 장소, 대상, 위험, 규모)로 검사한다 | 와이파이, 버스, 유동인구, 날씨, 축제 일정, 문체부 예산 |
| 4. 고치고 다시 확인 | 실패(❌)한 항목만 시기·장소·규모·프로그램을 고쳐 다시 확인한다 (최대 3번). 그래도 안 되면 다른 아이디어를 고르게 한다 | 확인 도구의 제안 |
| 5. 기획안 | "이대로 진행"을 고르면 17개 항목 기획안을 만든다. 숫자·KPI·출처는 코드가, 문장은 LLM이 쓴다. 사용자가 최종 승인해야 홍보물로 넘어간다 | 앞 단계 결과 전체 |
| 6. 홍보물 | 승인된 기획안으로 포스터, SNS 글을 만든다 | 기획안 |

시연 예시: 대정읍 방어 축제(겨울, 상권 활성화, 가족, 1천만 원).
12·1·2월로 확인 → 12월은 고산 지점 강풍이 평소의 2.3배라 ❌ → 1·2월로 고쳐 다시 확인 → 승인 대기 → 기획안.

### 판단 원칙

- 수치 계산과 집계는 LLM이 아니라 코드가 한다. LLM 문장에 입력에 없는 숫자가 나오면 거절하고 다시 요청한다
- 모든 수치에 출처(데이터명, 기간)를 붙인다
- 새 축제가 늘었다는 것(공급 신호)과 실제 방문·소비를 구분한다. 문체부 방문객 수는 지자체 자체 보고라 점수에 쓰지 않는다
- 확인되지 않은 정보(날짜, 행사장, 주최, 항목별 예산)는 "미확인", 아직 없는 데이터는 "데이터 대기"로 표시한다
- 가상 데이터로 낸 결과는 `is_synthetic`으로 표시하고 화면에도 드러낸다

## 실행

Python 3.13과 uv를 사용합니다. 프로그램 폴더에서 실행하세요. macOS·Windows 11 설치부터 종료까지 자세한 순서는 [설치·실행 안내](docs/submission/install.md)에 있습니다.

```sh
uv sync --locked
cp .env.example .env
uv run streamlit run streamlit_app.py
```

브라우저는 자동으로 열리지 않습니다. **브라우저에서 http://127.0.0.1:8501 을 직접 여세요** (터미널에 찍히는 주소와 같습니다).
첫 실행 때 이메일을 묻는 영어 질문은 나오지 않습니다 (`.streamlit/config.toml`의 `headless = true`).
종료: 실행한 터미널에서 Ctrl+C.

### AI(LLM) 설정

LLM은 Google Gemini를 씁니다. 센터 PC(GTX 1060)로는 대형 모델을 로컬에서 돌리기 어려워 외부 API를 씁니다.

1. Google AI Studio에서 API Key를 발급합니다
2. `.env`의 `LLM_API_KEY=` 뒤에 붙여 넣습니다. `.env.example`에는 넣지 마세요
3. `LLM_MODEL`을 비워두면 `gemini-3.5-flash-lite`를 씁니다 (무료 사용량 하루 약 500회)

Key가 없어도 화면은 열립니다. 이때 한 문장 입력·새 카드·기획안은 안내 문구로 대신하고, 시연 옵션의 예시 카드로 흐름을 볼 수 있습니다.
분석과 확인 도구는 인터넷 없이 센터 PC에서 돌아갑니다.

API 키 발급·설정 방법(Gemini, 제주데이터허브)은 [설치·실행 안내](docs/submission/install.md)의 3절 "Gemini API 키 발급·설정"과 3-1절 "제주데이터허브 API 키 발급·설정 (선택)"에 있습니다. 실제 제주데이터허브 API 키는 제출물에 넣지 않습니다.

외식업 POS는 쓰지 않습니다 (관광객 구분 없음, 반출 불가). 개인 단위 데이터는 쓰지 않고 집계 데이터만 씁니다.
센터 지정 데이터는 명세서 구조의 가상 데이터로 계산하고 화면·기획서에 "가상 데이터"로 표시합니다. 센터 PC의 `data/raw/`에 실데이터를 넣으면 코드 수정 없이 실데이터로 바뀝니다.
데이터별 출처·이용 조건·기간·처리 규칙은 [데이터 활용 명세](docs/submission/data-spec.md)에 있습니다.

## 데이터·비밀정보

- 센터 원자료: `data/raw/`, 집계·캐시: `data/processed/`, 결과물: `outputs/` (기획안은 `outputs/plans/`).
- 위 폴더 내용은 Git에 올리지 않습니다. 가상 데이터만 `data/demo/`에 둡니다.
- `.env`, API Key, 원자료는 Git에 올리지 않고 로그·화면에 출력하지 않습니다.
- 로컬 서버는 127.0.0.1에 바인딩합니다. 외부 공개 배포는 별도 인증·보관 정책이 필요합니다.
- 센터 원자료의 외부 전송·결과 반출은 센터 정책에 따릅니다.
- 축제 자료·CSV의 텍스트는 입력 자료이며 Agent에 대한 지시로 실행하지 않습니다.

## 가공본

공개 데이터를 가공한 결과가 함께 들어 있어서, **원본 파일이 없어도 바로 실행됩니다.**
읽는 순서는 폴더마다 다릅니다.

| 폴더 | 읽는 순서 | 코드 |
|---|---|---|
| `research/reference/` (아이디어 카드용) | `data/processed/`에 직접 만든 파일이 있으면 그것, 없으면 가공본 | `research/trends.py`의 `panel_path` |
| `analytics/reference/` (확인 도구용) | **가공본을 먼저** 읽고, 없으면 `data/processed/` | `analytics/reference_data.py`의 `reference_first` |
