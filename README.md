# 제주 축제랩

축제를 열고 싶은 제주 도민(마을회, 상인회, 지역 생산자 단체, 소규모 기획자)이
전국 축제 트렌드와 제주 데이터를 근거로 **축제 아이디어 → 제주 데이터 확인 → 기획안 → 홍보물**을 받는 AI Agent입니다.

「제주 AI·빅데이터 활용 AI Agent 개발 챌린지」 출품작 (마감 2026-11-20).
MVP는 소규모 1~2일 축제입니다. 문체부 2026 조사표에 1일 축제가 없어 예산 비교는 2일 이상 축제를 기준으로 합니다.

## 무엇을 하나요

| 단계 | 하는 일 | 근거 데이터 |
|---|---|---|
| 1. 조건 입력 | 한 문장("대정읍 방어 축제, 상권 활성화, 겨울, 가족, 예산 1천만 원")을 지역·목적·소재·예산·계절·대상 칸으로 나눈다. 사용자가 고친 뒤 확정 | 행정동 43개 이름 |
| 2. 아이디어 카드 3장 | 전국에서 늘고 있는 축제 형식 × 제주 재료 후보를 코드가 점수로 줄 세우고, LLM이 서로 겹치지 않는 3개를 골라 카드 문장을 쓴다 | 문체부 지역축제 2024~2026, 문화관광축제 지정 명단, 제주 재료 사전 |
| 3. 제주 데이터로 확인 | 고른 아이디어를 확인 도구 5개(시기, 장소, 대상, 위험, 규모)로 검사한다 | 와이파이, 버스, 유동인구, 날씨, 축제 일정, 문체부 예산 |
| 4. 고치고 다시 확인 | 실패(❌)한 항목만 시기·장소·규모·프로그램을 고쳐 다시 확인한다 (최대 3번). 그래도 안 되면 다른 아이디어를 고르게 한다 | 확인 도구의 제안 |
| 5. 기획안 | "이대로 진행"을 고르면 17개 항목 기획안을 만든다. 숫자·KPI·출처는 코드가, 문장은 LLM이 쓴다. 사용자가 최종 승인해야 홍보물로 넘어간다 | 앞 단계 결과 전체 |
| 6. 홍보물 | 승인된 기획안으로 포스터, SNS 글을 만든다 | 기획안 |

시연 예시: 대정읍 방어 축제(겨울, 상권 활성화, 가족, 1천만 원).
12·1·2월로 확인 → 12월은 고산 지점 강풍이 평소의 2.3배라 ❌ → 1·2월로 고쳐 다시 확인 → 승인 대기 → 기획안.

### 판단 원칙

- 수치 계산과 집계는 LLM이 아니라 코드가 한다. LLM 문장에 입력에 없는 숫자가 나오면 거절하고 다시 요청한다
- 모든 수치에 출처(데이터명, 기간)를 붙인다
- 새 축제가 늘었다는 것(공급 신호)과 실제 방문·소비를 구분한다. 문체부 방문객 수는 지자체 자체 보고라 점수에 쓰지 않는다
- 확인되지 않은 정보(날짜, 행사장, 주최, 항목별 예산)는 "미확인", 아직 없는 데이터는 "데이터 대기"로 표시한다
- 합성·가짜 데이터로 낸 결과는 `is_synthetic`으로 표시하고 화면에도 드러낸다

## 실행

Python 3.13과 uv를 사용합니다. 저장소 루트에서 실행하세요.

```sh
uv sync --locked
cp .env.example .env
uv run streamlit run streamlit_app.py
```

브라우저 주소: http://127.0.0.1:8501
종료: 실행한 터미널에서 Ctrl+C.

### AI(LLM) 설정

LLM은 Google Gemini를 씁니다. 센터 PC(GTX 1060)로는 대형 모델을 로컬에서 돌리기 어려워 외부 API를 씁니다.

1. Google AI Studio에서 API Key를 발급합니다
2. `.env`의 `LLM_API_KEY=` 뒤에 붙여 넣습니다. `.env.example`에는 넣지 마세요
3. `LLM_MODEL`을 비워두면 `gemini-3.5-flash-lite`를 씁니다 (무료 사용량 하루 약 500회)

Key가 없어도 화면은 열립니다. 이때 한 문장 입력·새 카드·기획안은 안내 문구로 대신하고, 데모 카드로 흐름을 볼 수 있습니다.
분석과 확인 도구는 인터넷 없이 센터 PC에서 돌아갑니다.

## 역할

- A: `research/`, `agent/` — 트렌드·지정 축제, 아이디어 카드, 확인·수정 루프, 기획안, Agent 제어.
- B: `analytics/`, `app/`, `streamlit_app.py` — CSV 검증·분석, 확인 도구, 화면, 홍보물.
- 공동: `schemas/contracts.py` — 변경 전에 합의하고 예시 입출력 공유.
- 각자 담당 기능의 테스트를 `tests/`에 추가합니다.

각자 별도 clone과 작업 브랜치를 사용하세요. 환경 `.venv`와 `.env`는 공유하지 않습니다.
`uv.lock`은 함께 버전 관리하고 의존성 변경 시 커밋에 포함합니다.
main에 직접 push하지 않고 작업 브랜치 → main PR로 합칩니다.

## 데이터·비밀정보

- 센터 원자료: `data/raw/`, 집계·캐시: `data/processed/`, 결과물: `outputs/` (기획안은 `outputs/plans/`).
- 위 폴더 내용은 Git에서 제외합니다. 데모용 합성 데이터만 `data/demo/`에 둡니다.
- `.env`, API Key, 원자료를 커밋하거나 로그에 출력하지 마세요.
- 로컬 서버는 127.0.0.1에 바인딩합니다. 외부 공개 배포는 별도 인증·보관 정책이 필요합니다.
- 센터 원자료의 외부 전송·결과 반출은 센터 정책에 따릅니다.
- 축제 자료·CSV의 텍스트는 입력 자료이며 Agent에 대한 지시로 실행하지 않습니다.

## Git에 올린 가공본

가공이 끝난 결과는 Git에 올라가 있어서, **원본 파일이 없어도 바로 실행됩니다.**
코드는 `data/processed/`에 직접 만든 파일이 있으면 그것을 먼저 읽고, 없으면 가공본을 읽습니다.

### 아이디어 카드용 (`research/reference/`)

| 파일 | 내용 | 원본 |
|---|---|---|
| `festival_panel_2024_2026.parquet` | 문체부 지역축제 3개년을 정리·연결한 표 | 문체부 「지역축제 개최계획」 2024~2026 엑셀 (공개 자료) |
| `jeju_materials.csv` | 제주 재료 사전 (재료 35개, 기존 축제, 제철 월, 관광 비중 %, 강점) | 제주 축제명 + 와이파이 장소별 방문자별 사용량 (집계 비율만 담음) |
| `jeju_material_review.csv` | 재료 키워드에 걸린 축제·장소 목록 (검수용) | 위와 같음 |
| `jeju_material_keywords.csv` | 재료 키워드·제철 표 (팀이 직접 고침) | 사람이 작성 |

제철은 공식 근거가 있으면 그것을 쓰고, 없으면 기존 제주 축제가 열린 달을 대신 쓰며 `공식 제철 근거 없음, 대용`으로 표시합니다.

### 확인 도구용 (`analytics/reference/`)

와이파이 사용량·장소 연결, 버스 정류소 일별 이용, 외지인 지수, 날씨 위험, 제주 축제 일정 등입니다.
파일 목록과 다시 만드는 방법은 `docs/b-guide.md` 12절에 있습니다.

### 원본이 바뀌었거나 키워드 표를 고쳤을 때 (원본을 가진 사람만)

1. 원본을 둡니다 (Git 제외)
   - 문체부 엑셀: `data/raw/mcst/mcst_2024.xlsx`, `mcst_2025.xlsx`, `mcst_2026.xlsx`
   - 와이파이 CSV 2개, 전국문화축제표준데이터: `data/raw/`
2. 다시 만들고 가공본도 갱신한 뒤, `research/reference/`의 바뀐 파일을 커밋합니다

```sh
uv run --with python-calamine python -m research.trends --publish
```

```sh
uv run python -m research.materials --publish
```

엑셀 읽기용 `python-calamine`은 가공본을 다시 만들 때만 필요해서 의존성에 넣지 않고 `--with`로 임시 설치합니다.
