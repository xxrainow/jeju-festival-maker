# 데이터 활용 명세

제주 축제 메이커이 쓰는 데이터의 출처, 이용 조건, 기간, 쓰는 곳, 처리 규칙을 정리했습니다.
- 자세한 점검 기록: `docs/data-check.md`
- 도구별 설명: `docs/b-guide.md`
- 판단에 쓴 숫자는 모두 코드가 계산합니다. 화면과 기획서에는 숫자마다 출처(데이터 이름, 기간)를 붙입니다.

## 1. 데이터 이용 원칙

- **집계 데이터만** 씁니다. 개인 단위 데이터(예: 3-05, 3-06 개인 이동 자료)는 쓰지 않습니다.
- 센터 지정 데이터의 **원자료는 센터 밖으로 내보내지 않습니다.** 분석·시각화한 가공 결과만 내보냅니다. 원자료는 `data/raw/`에 두고 Git·제출물에서 뺍니다.
- 외식업 POS 데이터는 쓰지 않습니다 (관광객을 구분할 수 없고 반출이 안 됨).
- 문체부 지역축제 계획 엑셀의 담당자 칸(소속, 부서, 직급, 성명, 연락처)은 읽지 않습니다. 저장 전에 전화번호·이메일 모양을 검사해, 있으면 멈춥니다.
- 사람 수가 아닌 값(와이파이 데이터 사용량)은 사람 수로 말하지 않습니다.
- 지자체가 스스로 보고한 축제 방문객 수는 참고로만 보여주고 점수에 쓰지 않습니다.
- 아직 받지 못한 센터 데이터는 명세서 구조의 **가상 데이터**로 계산합니다. 화면·기획서·홍보물에 "가상 데이터"로 표시합니다 (3절).
- 축제 자료와 CSV 안의 글은 입력 자료로만 다루고, 프로그램에 대한 지시로 실행하지 않습니다.

## 2. 사용 데이터

확인 도구 5개: **시기**(`check_timing`), **장소**(`check_venue`), **대상**(`check_target`), **위험**(`check_risk`), **규모**(`check_budget`).

### 2-5. 사용자 입력

지역, 목적, 관심 소재, 계절, 대상, 예산 상한. 모두 선택입니다. 확인되지 않은 정보(행사장 비용, 숙박, 날짜, 주최)는 AI가 채우지 않고 "미확인"으로 둡니다.

### 2-6. 데이터 특성 메모: 와이파이 연령대

- 와이파이 사용자 현황의 연령대 값은 7종뿐입니다: 10대 미만, 10대, 20대, 30대, 40대, 50대, 60대 이상.
- **2020-07부터 60대 이상이 급감하고 50대가 늘었습니다.** 60대 이상이 50대로 합쳐져 집계되는 것으로 보입니다.

| 연월 | 10대 미만 | 50대 | 60대 이상 |
|---|---|---|---|
| 2020-01 | 0.91% | 12.2% | 4.8% |
| 2020-06 | 0.48% | 14.7% | 3.2% |
| 2020-07 | 0.31% | 18.9% | 1.4% |
| 2021-01 | 0.13% | 25.8% | 0.7% |

- 대상 확인 기간(2023-01~2025-09)의 제주 전체 비중: 60대 이상 0.098%, 10대 미만 0.005%.
- 그래서 대상 확인은 다음처럼 합니다.
  - 어르신·영유아만 대상이면 "데이터 대기"로 둡니다.
  - 가족은 30·40대로만 판정하고 "10대 미만은 자료가 거의 없어 제외"를 적습니다.

### 3-2. 실데이터로 바꾸기 — `data/raw/`에 두면 먼저 씁니다

센터에서 받은 CSV를 `data/raw/` 폴더에 넣고 프로그램을 다시 실행하면 됩니다. 파일 이름에 아래 말이 들어 있으면 가상 데이터 대신 실데이터를 먼저 씁니다. 코드는 고치지 않아도 됩니다.

| 데이터 | 파일 이름에 들어갈 말 (하나 이상) | 형식 |
|---|---|---|
| 4-11 유동인구 | `4-11` 또는 `유동인구(읍면동)` | `.csv` 또는 `.csv.gz`, 명세서 컬럼 |
| 3-04 정류소별 이용 | `3-04` 또는 `정류소별 이용` | 위와 같음 |
| 3-10 교통량 | `3-10` 또는 `교통량` | 위와 같음 |
| 3-07 도로 구간 | `3-07`, `도로 구간`, `도로구간` | 위와 같음 |
| 3-08 도로 노드 | `3-08`, `도로 노드`, `도로노드` | 위와 같음 |

1. 파일을 `data/raw/`에 넣습니다. 예: `data/raw/4-11_내국인유동인구_읍면동_202505.csv`
2. 프로그램을 껐다가 다시 실행합니다. 자료는 실행할 때 한 번 읽습니다.
3. 4-11은 검사(`analytics/validate_flow.py`: 컬럼, 코드 값, 날짜, 음수 등)를 통과해야 씁니다. 통과하지 못하면 가상 데이터도 쓰지 않고 그 확인만 건너뜁니다.
4. 실데이터로 바뀌면 해당 결과의 "(가상 데이터)" 표시가 사라집니다.
5. 4-11 실데이터가 **12개월 이상** 쌓이면 시기 확인의 외지인 지수를 4-11로 다시 만들 수 있습니다.

   ```sh
   uv run python -m analytics.check_timing --build --flow data/raw/<4-11 파일>
   ```

`data/raw/`는 Git과 제출물에서 빠집니다. 센터 원자료는 센터 PC 안에서만 씁니다.

### 3-3. Git에 올린 가공본 (원자료 없이 바로 실행)

원자료가 없는 PC(센터 PC 포함)에서도 바로 돌아가도록, 공개 데이터로 만든 가공 결과를 저장소에 넣었습니다.

| 폴더 | 파일 | 읽는 순서 |
|---|---|---|
| `analytics/reference/` (확인 도구용, 약 4.9MB) | 와이파이 사용량 집계(`wifi_usage_by_place_month_type.parquet`), 장소 → 행정동·좌표(`area_link_wifi.csv`), 성·연령 표, 장소 후보, 정류소 일별 이용, 이웃 동네, 외지인 지수, 제주 축제 일정, 날씨 위험(주별·월별), 동네별 날씨 지점, 시간대 승차 비중, 관측지점 | **가공본을 먼저** 읽고, 없으면 `data/processed/` |
| `research/reference/` (아이디어 카드용) | 문체부 축제 3개년 패널, 제주 재료 사전·키워드·검수표 | `data/processed/`에 직접 만든 것이 있으면 그것, 없으면 가공본 |

원자료가 바뀌었을 때 다시 만드는 방법은 3-4절에 있습니다.

### 3-4. 가공본 다시 만들기

**앱을 실행할 때는 이 절이 필요 없습니다.** 가공본이 저장소와 제출 ZIP에 들어 있습니다. 공개 데이터 원본부터 가공본을 다시 만들 때만 씁니다.

**데이터를 다루는 원칙**
- **큰 공개 데이터 원본(와이파이 사용량·사용자 현황, 버스 이용 원자료 등)은 저장소(GitHub)에 올리지 않습니다.** 용량이 크고 각 기관에서 받을 수 있기 때문입니다. 제출 ZIP에는 넣을 수 있습니다.
- 허브 API 원본(정류소·와이파이 AP·숙박·관광지 4종, `data/raw/jejuhub_*.csv`)도 저장소에 올리지 않습니다. **`data/raw/`에서만 쓰고, 가공본을 만들 때만 필요합니다.** 앱은 이 원본으로 만든 가공본(예: 와이파이 장소 → 행정동·좌표 `area_link_wifi.csv`)만 읽습니다.
- **센터 비공개 데이터(4-11, 3-04, 3-07·3-08·3-10 등)는 센터 PC 안에서만 씁니다.** 이 데이터로 만든 집계 결과도 센터 밖으로 가져가려면 반출 승인을 받아야 합니다. 이 절의 명령은 공개 데이터만 씁니다.

**2) 순서대로 실행**

프로그램 폴더에서 아래 순서대로 실행합니다. 앞 단계의 결과(`data/processed/`)를 뒤 단계가 읽습니다.

```sh
uv run python -m analytics.fetch_jeju_hub                      # ① 허브 API 4종 → data/raw/jejuhub_*.csv (JEJU_HUB_KEY 필요)
uv run python -m analytics.build_wifi_usage                    # ② 와이파이 사용량 장소·월·방문유형 집계
uv run python -m analytics.weather                             # ③ 날씨 위험 표, 동네별 날씨 지점, 관측지점 좌표
uv run python -m analytics.candidate_compare                   # ④ 후보지 비교표, 법정동 → 행정동 변환표
uv run python -m analytics.budget_benchmark                    # ⑤ 문체부 2026 예산 기준, 제주 축제 → 행정동
uv run python -m analytics.real_checks --build                 # ⑥ 확인 도구 5개용 표 (외지인 지수, 축제 날짜, 성·연령, 장소, 정류소)
uv run python -m analytics.reference_data                      # ⑦ 위 결과를 analytics/reference/에 복사 (가공본 갱신)
uv run --with python-calamine python -m research.trends --publish   # ⑧ 문체부 3개년 축제 패널 → research/reference/
uv run python -m research.materials --publish                  # ⑨ 제주 재료 사전·검수표 → research/reference/
```

- ①은 이미 `data/raw/jejuhub_*.csv`가 있으면 건너뛰어도 됩니다. 키 발급·설정은 [install.md](install.md) 3-1절에 있습니다.
- ⑥은 와이파이 사용량 집계와 장소 연결을 `analytics/reference/`에서 먼저 읽습니다. **와이파이 원자료가 바뀌었으면 ⑦까지 한 번 실행한 뒤 ⑥·⑦을 한 번 더 실행**하세요.
- ⑧의 `python-calamine`은 엑셀 읽기용입니다. 가공본을 만들 때만 필요해서 의존성에 넣지 않고 `--with`로 잠시 설치합니다.
- 다 끝나면 `analytics/reference/`, `research/reference/`의 바뀐 파일을 확인합니다. `data/raw/`와 `data/processed/`는 Git에서 빠져 있습니다.
